## Question and method

Which functions should the shared Drafter queue (`docs/drafter-runbook.md`, `tools/work_queue.py`)
hold first, for sessions that draft unattended with a skeleton and a one-page sheet per function?
The same planner and filters as `findings/fifth-batch-selection.md` (`export_pack.py plan --order
cheap`), restricted to small tasks (`--normal-functions 0`, so every function is at most 64 bytes)
and to about 40 functions. Classes with a unit in `reconstruction/` or an open task directory are
left out, which keeps every pending wave-3 task and every unit another session is drafting out of
this selection.

## Observations

- Eligible after all filters: 1,118 functions; 686 after one per L1 cluster. Removed by the cheap
  filters after the inventory ones: existing unit or open task 944, exception data 539, no verified
  skeleton 213, families too small for a task 91, parked family 34, thread-local read 12.
- Selected: **42 functions, 1,217 bytes, 17 classes** in 2 small tasks (17 units): a TESBoundObject
  family (8 units, 20 functions) and a NiObject family (9 units, 22 functions).
- Size bands: at most 32 bytes 28; 33 to 64 14. Areas: forms 20, netimmerse 14, bsengine 8.
- Name sources of the first usable name: NG slot 39, meh321 3. FNV counterpart: 2 functions.
- Clusters: 20 of the 42 are members of an L1 cluster with more than one member (each the only one
  of its cluster here).

## Interpretation and alternatives

The queue puts these units after the unfinished units of the wave-3 group `batch5-s03-niobject`,
which are re-queued with fresh skeletons. A larger selection is one planner run away; it was kept
small so that the first measured queue runs say something about each model before more is queued.
