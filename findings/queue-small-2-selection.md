## Question and method

Which further functions can the shared Drafter queue hold once `findings/queue-small-1-selection.md`
is drained? The same planner and filters (`export_pack.py plan --order cheap`, small tasks only, every
function at most 64 bytes), asked for up to 1,000 functions, with one change: a class family too small
for a 10-function group task is kept, since a queue unit is one class. Afterwards a function is left
out when it falls in the same L1 cluster as a matched function or as one that passed in a queue
session (those are for the stamping lane), when its name follows a pattern that collided with the
published symbol map (`GetFormEditorID`, `InitItemImpl`), or when its class is a template.

## Negative results and limitations

Same limits as the fifth-batch selection (thread-local scan of the function's own bytes only; the
parked census is per function). The L1 cluster test is the function table's normalised-byte hash, not
a byte-for-byte proof of identity. No pass rate is predicted. Rows are added to `data/progress.json`
as `mapped`.
